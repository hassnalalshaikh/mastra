# FirecrawlBrowser class

The `FirecrawlBrowser` class provides browser automation backed by the [Firecrawl Browser Sandbox](https://docs.firecrawl.dev/features/browser). It provisions remote browser sessions through the Firecrawl API and connects to them over the Chrome DevTools Protocol (CDP).

`FirecrawlBrowser` extends [`AgentBrowser`](/reference/browser/agent-browser) and exposes the same deterministic toolset. Use it when you want hosted browser sessions instead of a local Chromium install. For local automation, see [`AgentBrowser`](/reference/browser/agent-browser). For AI-powered interactions using natural language, see [`StagehandBrowser`](/reference/browser/stagehand-browser).

## Usage example

```typescript title="src/mastra/agents/index.ts"
import { Agent } from '@mastra/core/agent'
import { FirecrawlBrowser } from '@mastra/browser-firecrawl'

const browser = new FirecrawlBrowser({
  apiKey: process.env.FIRECRAWL_API_KEY,
  firecrawl: {
    ttl: 600,
  },
})

export const browserAgent = new Agent({
  id: 'browser-agent',
  name: 'Browser Agent',
  instructions: `You can browse the web. Use browser_snapshot to see the page structure,
then interact with elements using their refs (e.g., @e5).`,
  model: '__GATEWAY_OPENAI_MODEL__',
  browser,
})
```

## Transport controls

The pinned transport contribution accepts an explicit allowlist of SDK options. Credentials and the API endpoint remain separate constructor options.

```typescript
import { FirecrawlBrowser } from '@mastra/browser-firecrawl'

const browser = new FirecrawlBrowser({
  apiKey: process.env.FIRECRAWL_API_KEY,
  clientOptions: { timeoutMs: 20_000, maxRetries: 1, maxRedirects: 0 },
})
```

These options apply to SDK session creation and cleanup in both scopes. The timeout and redirect policy also apply to HTTP CDP discovery. They don't limit CDP actions or replace the session's `firecrawl.ttl`. Omitting the options preserves existing defaults. This public contract requires the paired SDK transport contribution; the stock SDK version label alone doesn't identify it.

## Session lifecycle

The pinned browser contribution also accepts `sessionLifecycle` observations. `beforeCreate({ threadId })` runs before the paid request; `created({ sessionId, threadId })` runs after provisioning; `deleted({ sessionId, threadId, receipt })` receives the provider's confirmed deletion response, including available duration and billed credits. These hooks are awaited. A failed deletion or observation keeps cleanup pending, and confirmed receipts can be observed again without issuing a second deletion. `assertCleanupSettled()` surfaces any incomplete cleanup.

Shared sessions retain AgentBrowser's viewer preferences, saved tabs, trusted input observation and idle closure. A failed close can be retried through the native `close()` method. This enhanced behavior belongs to the pinned contribution until an accepted stable upstream replacement is adopted.

The contribution exposes `ownsProviderSession(sessionId)` to check this instance's retained cleanup identity. A persisted native workflow can release an exact recorded resource through `FirecrawlBrowser.deleteProviderSession({ apiKey, sessionId, apiUrl?, clientOptions? })`. This returns the confirmed provider deletion response without launching another browser. The workflow caller must verify the record's owner before supplying the identity and credentials. Pass the same `clientOptions` when the recorded cleanup request needs explicit transport bounds.

`createThreadManager(options)` can return a subclass of the public `FirecrawlAgentBrowserThreadManager`, including one that checks restored page URLs before navigation. The supplied options retain native provider ownership and cleanup. Returning another manager type is rejected.

Session provisioning depends on the `scope` option inherited from `AgentBrowser`:

- `'thread'` (default): Each conversation thread gets its own Firecrawl sandbox session, created on first use and deleted when the thread's browser session is destroyed.
- `'shared'`: One Firecrawl sandbox session is created when the browser launches and shared across all threads. The session is deleted when the browser closes.

In both cases, `FirecrawlBrowser` deletes the remote Firecrawl session when the browser closes, including when session creation or connection fails partway through.

## `resolveCdpWebSocketUrl(url, logger?, options?)`

This public helper resolves an HTTP endpoint through `/json/version` and returns its WebSocket debugger URL. WebSocket URLs pass through without a discovery request.

The optional `CdpResolveOptions` contains `timeoutMs` and `maxRedirects?: 0`. The discovery timeout defaults to 10,000 milliseconds and must be positive and finite. Set `maxRedirects: 0` to reject HTTP redirects; omission preserves the default redirect behavior. Unsupported redirect values and invalid timeouts throw before discovery. The helper rejects failed responses, missing debugger URLs and timeout failures.

`FirecrawlBrowser` provides the same toolset as `AgentBrowser`, including `browser_goto`, `browser_snapshot`, `browser_click`, `browser_type`, and `browser_screenshot`. See the [`AgentBrowser` tool reference](/reference/browser/agent-browser) for the full list and tool parameters.
