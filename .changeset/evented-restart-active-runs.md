Evented (and scheduled) workflow runs orphaned by a lost process can now be recovered. Set `options.autoRestartActiveRuns: true` on the workflow and `recovery: { workflows: 'auto' }` on `Mastra` (or call `mastra.restartAllActiveWorkflowRuns({ optedInOnly: true, staleAfterMs, createdBefore })`). Once workers start, Mastra sweeps and then sweeps again every `workflowRunSweepIntervalMs` (default 5 minutes); it restarts only opted-in runs created before this process started its workers whose snapshot has not changed for `workflowRunStaleAfterMs` (default 20 minutes), re-checked right before the restart, under a pubsub recovery lease when the pubsub provides one. A sweep starts each restart without waiting for the run to finish, and a run whose restart fails 3 times in a process is marked `failed` with the reason. Because the evented engine does not record its active position while running, the restart position is recovered from the step graph and the recorded results (sequential steps, parallel branches, foreach iterations by their recorded status, nested workflows); positions it cannot recover are refused. `autoRestartActiveRuns: false` opts a workflow out of the generic sweep, as upstream.
